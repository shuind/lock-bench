# 内存压力下的采集成本

64 MiB 限额，256 MiB 文件映射与 16 MiB 匿名内存；4 线程扫描 15 遍。普通 mmap_lock tracepoint 对比计数、状态、入口栈，轮询作为附录。

## 测量范围

扫描程序在独立 cgroup v1 中，内存和内存＋swap 限额均为 64 MiB，swappiness=0。扫描前建立 256 MiB 文件只读共享映射，另触碰并保留 16 MiB 匿名内存。

4 个线程各负责四分之一映射，正式扫描 15 遍，每页只读开头的 8 字节数字并累计校验。4 KiB 页面共 65,536 个，合计 983,040 次页面访问；这不是缺页次数或锁次数。正式窗口没有反复 mmap/munmap；映射关系保持，页面驻留、页表项、回收和 refault 会变化。

准备文件、映射、预热、创建线程、加载/卸载探针、最终导出均在扫描计时外。实际缺页、回收、I/O 等工作不会因为固定访问量就完全相同，需结合原始压力指标和系统起止快照判断波动。

本 case 用同一二进制切换计数、状态、入口栈和状态＋轮询。7 个随机区组，每组含 1 基线＋4 观测配置，共 35 次正式运行、28 个对照。主 CPU 合计扫描、控制与观测程序；报告主表显示前三档，轮询放在附录。

轮询每 100 ms 看状态，阈值 1 秒；正式成本轮没有超时取栈。另用真实 mprotect/maps 争用夹具验证当前等待栈，间隔和阈值缩短为 1 ms，验证记录不混入成本统计，不能称为真实死锁或 1 秒锁等待。

## 结果

7 个区组，每组 1 基线＋4 配置，共 35 次运行、28 个对照。
